follows [Microsoft Calendar](../../Microsoft-calendar-tool.md#acceptance-plan-and-rollout).

## Upgrade, rollback and compatibility

- Follow the [current installation guide](../../INSTALLATION.md#upgrade-to-v762-existing-checkout)
  and [v7.6.1 → v7.6.2 migration](../../MIGRATION.md#v761-to-v762).
- Preserve operator configuration, SQLite data, OAuth caches and saved calendar
  IDs. Legacy Microsoft identity mismatches require intentional operator
  correction, never fallback to another cached user/calendar.
- Invitations and working-hours/horizon enforcement remain off until opted in.
  Existing appointment-only arguments, saved prompts and captured Agent scope
  remain supported. Later-call/untracked mutations require staff.
- Same-call booking ownership is bounded/in-memory; restart/rollback loses it.
  Stable creation transaction IDs reconcile retries but do not turn availability
  checks into distributed exclusive reservations.
- Roll back outside active calls with the v7.6.1 code/images and pre-update
  configuration. No database/ID/cache downgrade is needed; Graph events remain.
  Never delete existing appointments as rollback cleanup.
- `farewell_hangup_delay_sec` is ignored/deprecated but YAML/API-compatible.
  Caller-facing drain and Local AI's independent farewell settings remain.
