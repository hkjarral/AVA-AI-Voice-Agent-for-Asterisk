## Security assessment

### Manifest snapshot

GitHub's 2026-11-22 snapshot has **7 open alerts: 1 critical, 3 medium and 3 low**.
The already-merged #712 updates the Torch/Transformers set; the former 39-alert
baseline must not be copied forward as current. Advisory severities can change,
so a numerical decrease alone is not proof that every previous finding was fixed.

| Package | Severity | Advisory | Disposition |
| --- | --- | --- | --- |
| `python-jose` | critical | [GHSA-3qf3-8w2g-rqmx](https://github.com/advisories/GHSA-3qf3-8w2g-rqmx) | No patched version reported in the snapshot. AVA decodes only HS256 with a configured symmetric secret; assess that bounded exposure and retain the alert. |
| `minimatch` | medium | [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) | Frontend development dependency in the lockfile; fixed version reported as 11.0.1. Remediation remains separate dependency work. |

| `dompurify` | low | [GHSA-cg2g-xh64-v4q7](https://github.com/advisories/GHSA-cg2g-xh64-v4q7), [GHSA-mrv2-3pqr-j5jr](https://github.com/advisories/GHSA-mrv2-3pqr-j5jr), [GHSA-c6gr-qvv4-5v3f](https://github.com/advisories/GHSA-c6gr-qvv4-5v3f) | Monaco dependency; fixed version reported as 3.4.17. Admin authentication in `admin_ui/backend/auth.py` fixes `ALGORITHM = "HS256"`
and passes `algorithms=[ALGORITHM]` to `jwt.decode` using the private configured
secret. That is evidence against this advisory's asymmetric-public-key-as-HMAC
path in AVA's configuration, not a repaired `python-jose` package or universal
consumer clearance. Keep management interfaces private and retain strong secrets.

### Image and Bookworm evidence

The latest applicable [main Trivy run](https://github.com/hkjarral/AVA-AI-Voice-Agent-for-Asterisk/actions/runs/44453991747)
on `da7dddbc` completed with 10 unique Engine and 14 unique CPU Local AI results,
including high packaging findings for `jaraco.context 5.3.0` (CVE-2026-23949) and
`wheel 0.45.1` (CVE-2026-24049). The Local AI count includes Dockerfile configuration
findings; counts are not distinct CVE totals. The workflow uses `ignore-unfixed`
and a CPU core profile, so green status is completion, not security clearance.
A fresh scan of the frozen release-preparation head remains required.

Engine, Admin and updater retain Bookworm bases. On 2026-11-22 Debian's trackers
still list Bookworm zlib `1:1.2.13.dfsg-1` as vulnerable to
[CVE-2026-85091](https://security-tracker.debian.org/tracker/CVE-2026-85091)
and [CVE-2026-27171](https://security-tracker.debian.org/tracker/CVE-2026-27171);
the Trixie fixed version matches the CPU Local AI Dockerfile's enforced minimum.
This is current vendor/base-family evidence, not an independent inspection of
installed packages in every final candidate image. Recheck candidate artifacts
before publication; `ignore-unfixed` can hide these findings.

**Historical attribution correction:** the [v7.7.3 Bookworm assessment](v7.7.3-validation-matrix.md#bookworm-exposure)
also named CVE-2026-76844 as zlib. The [current Debian record](https://security-tracker.debian.org/tracker/CVE-2026-76844)
identifies webpack-dev-middleware instead. That ID is not carried forward as a
zlib finding. The historical record is preserved with this explicit correction;
no claim is made that another package's exposure was thereby fixed.

The local Docker daemon was unavailable during preparation, so no fresh local
base-image package inspection was performed. Required hosted image builds/scans
and the final artifact checks remain separate from this limitation.
