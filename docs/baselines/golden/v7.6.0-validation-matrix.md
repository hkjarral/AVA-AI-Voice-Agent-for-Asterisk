## Explicitly unqualified or deferred WebSocket scope

- WebSocket providers, pipelines, codecs, Asterisk versions, WSS/routed
  topologies, concurrency levels, transfers, DTMF, recordings, outbound and
  compliance flows, and failure modes not recorded as passing above remain
  unqualified. v7.6.0 does not turn PR #644's A1/A2 deferrals into passes.
- Experimental plain controls remain limited to exactly Asterisk 20.17.0 and
  protocol-level evidence. They are not a production provider qualification.
- PR #644's maintainability follow-ups M1-M4 remain deferred: duplicate setup
  and codec logic, WebSocket state ownership, per-frame performance, and
  module-requirement synchronization. No regression is known, but this release
  does not claim those audits or benchmarks are complete.
- This versioned matrix resolves the documentation-reconciliation portion of
  PR #644 A3 while retaining the original qualification boundary.

## Compatibility and rollback boundary

- v7.6.0 is an in-place release with additive automatic Call History schema
  changes and no `agents.db` migration.
- Existing installations retain AudioSocket or ExternalMedia RTP unless an
  operator explicitly selects and applies WebSocket.
- Persisted call metadata remains opt-in and non-authoritative. Disabling the
  policy stops future persistence without deleting historical values.
- Historical calls remain readable but cannot gain an effective-settings
  snapshot retroactively.
- The legacy logs export route remains callable but now returns a bounded,
  sanitized one-hour system package rather than an unbounded raw archive.
- Database rollback requires no down-migration. Before application rollback
  from WebSocket, drain calls, restore AudioSocket or ExternalMedia RTP, verify
  a smoke call, and restore prior-release-compatible configuration.
